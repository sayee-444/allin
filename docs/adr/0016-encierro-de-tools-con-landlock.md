# Cada proceso de tool se encierra a sí mismo con Landlock y solo alcanza lo que su function declara

Sin aislamiento, una tool aprobada podía escribir el Estado de Main, una Conversación o un `.py` en `functions/`, y leer las Conversaciones de otras Sesiones o `~/.ssh` y mandarlos por la red (riesgo aceptado en ADR-0013). Los hashes protegen las piezas, no el estado ni la privacidad. Por eso cada proceso de tool (ADR-0005) y de Proceso adherido (ADR-0012) se encierra a sí mismo al arrancar, antes de importar su function, y ADR-0001 se cumple por fuerza y no por buena conducta del código.

El encierro es Landlock, más un filtro seccomp mínimo. Landlock es una función del kernel de Linux (desde 5.13) con la que un proceso sin privilegios le pide al kernel "desde ahora, yo y todos mis hijos solo podemos tocar estas carpetas y conectar a estos puertos"; el kernel lo cumple y no se puede deshacer. Cubre archivos, TCP (bind y connect por puerto), señales hacia procesos fuera del encierro y sockets unix abstractos. No cubre UDP, así que con la red cerrada el filtro seccomp solo deja crear sockets `AF_UNIX`. Lo aplica el propio proceso, como `PR_SET_PDEATHSIG` en ADR-0012, sin `preexec_fn` (ADR-0003). Se descartó bubblewrap: necesita user namespaces sin privilegios, que distros como Ubuntu restringen con AppArmor, y obliga a que el proceso de la tool sea un `exec` de `bwrap` en vez de un `multiprocessing` spawn.

Lo que una function necesita se declara con el decorador `@reach` (su Alcance), como los demás decoradores (ADR-0009): `read`, `write`, `net` (`False`, `True` o una lista de puertos TCP; Landlock no filtra por host) y `display` (abre el socket de X11 o Wayland, porque un cliente gráfico puede leer el teclado de otras ventanas). Las rutas son raíces simbólicas (`work`, `home`, `/`) más una subruta. Sin decorador, el Alcance es el mínimo: leer y escribir en la Carpeta de trabajo de su Sesión, leer el sistema (`/usr`, `/lib*`, `/etc`, Python y el venv) y su propio módulo, y nada de red. `TMPDIR` apunta a `work/.tmp`; `/tmp` no se abre. Se restringen también las lecturas porque, si no, cualquier tool aprobada podría leer lo privado y sacarlo. En una fscreen, `@reach` va en la clase y vale para todo su Proceso adherido.

La Carpeta de trabajo de cada Sesión es `<carpeta de datos>/workspaces/<id>/`, fuera de `sessions/` y `state/`, porque la carpeta de la Sesión guarda su estado (Conversación, Log, Ajustes, functions). Solo un humano la puede apuntar a otra ruta (un repo suyo), con un Command main de Origen humano. Entre Sesiones nada se comparte por defecto: los archivos viajan como adjuntos de `/send` (ADR-0013), que Main copia a la carpeta de destino.

La carpeta de datos nunca entra en un Alcance, ni siquiera en uno amplio. Landlock solo da permisos sobre carpetas enteras: dar `home` daría también `~/…/var`, con el Estado de Main, las Conversaciones y las FIFOs. Por eso, al lanzar cada llamada, Main recorta la carpeta de datos: convierte `home` o `/` en permisos sobre cada carpeta hermana del camino hasta ella, y deja fuera solo esa rama. Con la carpeta de datos en `~/Pictures/Neva/var`, `write=["home"]` queda en todo `~` menos `Pictures`, todo `Pictures` menos `Neva` y todo `Neva` menos `var`. Así se le puede dar al LLM toda la libertad que se quiera sobre la máquina sin que alcance el estado de AllIn. Como se recalcula en cada llamada, solo se pierde crear entradas nuevas justo en esos niveles intermedios mientras dura la llamada. Se descartaron rechazar todo Alcance que contenga la carpeta de datos (haría imposible "toda la máquina") y permitirlo con un aviso (rompería ADR-0001 otra vez). Al implementarlo, el README lo explica con este ejemplo.

El Alcance es parte del código de la function, y por tanto de su hash aprobado (ADR-0013): ampliarlo es un cambio y la pieza vuelve a cuarentena. La aprobación lo muestra lo primero, resaltando lo que excede el mínimo, y al aprobar se puede reducir, igual que se añade `@confirm` (ADR-0014). Como ninguna tool puede escribir en `functions/` ni en `sysprompts/`, crear o cambiar una function, un Sysprompt, un Molde o un Plano desde una Sesión solo es posible por el Command session Crear, que ejecuta Main con Confirmación; una tool que lo intente recibe el error del sistema de archivos como salida normal. La recarga en caliente no cambia: cada llamada es un proceso nuevo que se encierra con el código y el Alcance actuales. Solo un Proceso adherido ya vivo conserva el encierro con el que arrancó, así que si su fscreen cambia de Alcance se vuelve a lanzar.

Una tool no deja procesos vivos. Sus subprocesos heredan el encierro, y su proceso se declara `PR_SET_CHILD_SUBREAPER` para que los nietos huérfanos vuelvan a él; al terminar la function, o al cancelarse, mata a todos sus descendientes antes de devolver el resultado, y si Main tiene que matarla por timeout hace `killpg` a su grupo. Lo que deba vivir entre llamadas es un Proceso adherido. El archivo compartido de un Proceso adherido se elige antes de lanzarlo (con Origen humano, o con Confirmación si lo pide una Sesión) y Main lo añade al Alcance de esa instancia; abrir otro archivo es lanzar otro Proceso adherido.

Al arrancar, Main comprueba la ABI de Landlock del kernel. Si falta todo o parte (la red necesita ABI 4, kernel 6.7), las piezas del propio usuario corren con un Aviso fijo de "sin aislamiento" que dice qué falta, y las de origen ajeno (de un Kit de otro autor o creadas desde una Sesión) no corren: el LLM recibe el error "este kernel no puede encerrar esta tool". Nada lo salta, ni `--devastation`, que salta Confirmaciones y no encierros.
