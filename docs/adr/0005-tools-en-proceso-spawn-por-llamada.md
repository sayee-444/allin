# Cada llamada a una tool corre en un proceso spawn propio

Las functions las puede escribir el LLM y se recargan en caliente; si corrieran dentro de Main, una tool colgada o que llame `os._exit()` congelaría o tumbaría todas las Sesiones. Cada llamada se ejecuta en un proceso `multiprocessing` en modo spawn (seguro con threads) con timeout de los Ajustes; cancelar el Turno hace `terminate()`, y las Command sessions que la tool dispare viajan al despachador por una `multiprocessing.Queue`. Se aceptan ~50–100 ms por llamada; se descartaron threads (no se pueden matar) y un pool persistente (estado global contaminado entre llamadas).

Cada proceso se encierra a sí mismo al arrancar, antes de importar la function, con lo que esta declara en `@reach` (ADR-0016). Como encerrada no puede leer el estado, cada Command session que dispara recibe su resultado de Main por un canal de vuelta, y la tool lo espera: así responden Consultar, el "encolado" de `/send` y el reinicio del Servidor (ADR-0009). No es esperar a otro Turno (ADR-0004), porque Main contesta en cuanto ejecuta el comando. El timeout cuenta solo el tiempo de la propia tool: lo que espera esa respuesta no cuenta, porque Main tiene sus propios límites (una Confirmación espera al humano; un reinicio del Servidor termina en `ready` o `failed`).
